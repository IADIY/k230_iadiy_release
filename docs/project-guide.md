# IADIY K230 Debian Project Guide

This is the operating guide for the IADIY K230 SDK tree. Our runtime target is Debian on the 01Studio CM-K230 eMMC board. Buildroot is still used by the SDK to produce boot artifacts, kernel modules, device-tree files, DEB packages, and the base image layout, but the final system image we flash is the Debian image generated by `make debian`.

[Project overview](../README.md) · [Vendor SDK README](README.md)

Commands below run from the repository root unless stated otherwise.

## Project Scope

- Runtime OS: Debian, generated by the SDK distribution flow.
- Board: 01Studio CM-K230 Base Board, eMMC variant.
- Main board config: `k230_canmv_01studio_emmc_defconfig`.
- Main source overlay: `buildroot-overlay/`.
- Generated build output: `output/`.
- Download/source cache: `dl/`.

Treat `output/`, `dl/`, downloaded tarballs, local config files, and generated images as build state, not source.

## Setup

Install the SDK toolchain and host dependencies:

```bash
sudo make toolchain_and_depend
```

The setup script is [tools/install_toolchain_and_depend.sh](../tools/install_toolchain_and_depend.sh). The [vendor README](README.md) says the SDK has been verified on Ubuntu 22.04 and 24.04.

## Boot Logo Artwork

The 01Studio SD-card and eMMC configurations share the U-Boot logo stored at
`buildroot-overlay/board/canaan/k230-soc/logo/logo_01.yuv`. The post-image
script installs it as `/logo.yuv` in the boot partition, so Buildroot, Debian,
and Ubuntu images all inherit the same picture.

Original artwork is tracked for future selection under:

```text
buildroot-overlay/board/canaan/k230-soc/logo/source/
```

The active artwork is stored under the fixed names `logo_01.png` and
`logo_01.yuv`. To change the boot picture, prepare the new files and replace
that pair without changing the U-Boot configuration. The PNG is the reviewable
480x800 source; the YUV must be an 800x480 raw NV12 file of exactly 576000
bytes.

The original vendor `b.sh` is retained as an FFmpeg conversion reference. Its
commands cover multiple panel sizes, so run the command appropriate for the
target image instead of treating the whole file as an automated build step.
The currently selected artwork is `source/IADIY_IG_boot_image.png`, rotated
clockwise for the 01Studio portrait display.

After changing the logo, regenerate the base image before building a
distribution image:

```bash
make CONF=k230_canmv_01studio_emmc_defconfig
make buildroot
sudo make debian   # or: sudo make ubuntu
```

## Build Debian Image

Select the eMMC board configuration and build the base SDK image as your normal
user:

```bash
make CONF=k230_canmv_01studio_emmc_defconfig
make buildroot
```

`make CONF=...` selects the configuration and runs the default build target;
`make buildroot` resumes the selected build and regenerates its base images.

Then generate the Debian image:

```bash
sudo make debian
```

`sudo make debian` runs [buildroot-overlay/board/canaan/k230-soc/distribution/distribution.sh](../buildroot-overlay/board/canaan/k230-soc/distribution/distribution.sh). It:

- Requires `output/k230_canmv_01studio_emmc_defconfig/images/sysimage-sdcard.img`.
- Downloads or reuses `debian13.tar.gz`.
- Verifies the Debian rootfs tarball MD5.
- Copies kernel modules, `sta.sh`, selected libraries, camera/media services, and DEB package contents into the Debian rootfs.
- Replaces the base rootfs partition with the Debian rootfs.
- Produces `debian.img.gz` and a versioned symlink.

Expected output directory:

```text
output/k230_canmv_01studio_emmc_defconfig/images/
```

Important output files:

| File | Meaning |
|---|---|
| `debian.img.gz` | Final Debian image to flash |
| `k230_canmv_01studio_emmc_debian_*.img.gz` | Versioned symlink to `debian.img.gz` |
| `sysimage-sdcard.img.gz` | Base SDK/Buildroot image, not our normal runtime target |
| `Image` | Kernel image |
| `k230-canmv-01studio-emmc-lcd.dtb` | Default DTB for this no-HDMI board |
| `debian13.tar.gz` | Cached Debian rootfs tarball |

Useful commands:

| Command | Purpose |
|---|---|
| `make list_def` | Show supported defconfigs |
| `make help` | Show SDK targets |
| `make buildroot` | Resume the selected configuration and regenerate its images |
| `sudo make debian` | Regenerate the Debian image from existing base artifacts |
| `sudo make debian_rootfs` | Print the manual Debian rootfs generation script |

`sudo make debian` packages files that already exist in the selected Buildroot
output. It does not compile changed packages, the kernel, DTBs, or bootloader.
Rebuild the changed component first, regenerate the base image, and then rerun
`sudo make debian`.

### IMX335 Variant

The IADIY IMX335 UVC profile preserves the 01Studio eMMC board configuration,
switches VVCAM's default sensor to IMX335, and includes FFmpeg and the manual
`k230-camera` USB camera application.

Build the variant and its Debian image with:

```bash
make CONF=k230_canmv_iadiy_emmc_imx335_uvc_defconfig
make buildroot
sudo make debian
```

The expected artifacts are:

```text
output/k230_canmv_iadiy_emmc_imx335_uvc_defconfig/images/debian.img.gz
output/k230_canmv_iadiy_emmc_imx335_uvc_defconfig/images/*_debian_*.img.gz
```

The versioned image name is a symlink to `debian.img.gz`; flash
`debian.img.gz` (or that symlink) to the 01Studio eMMC board. The original
`k230_canmv_01studio_emmc_defconfig` remains the GC2093 configuration.

The initial software/hardware assumptions for this variant are:

- The IMX335 module is electrically and mechanically compatible with the
  01Studio camera connector.
- The current IMX335 driver uses `/dev/i2c-0`, sensor address `0x1a`, a 24 MHz
  input clock, and two MIPI data lanes.
- VVCAM mode 1 is 2592x1944 at a nominal 30 fps, RAW12, with matching
  full-resolution ISP tuning files.

## Incremental Build Commands

Buildroot records completed steps with stamp files under
`output/<CONF>/build/`. You normally need to rebuild only the component whose
source or configuration changed. Run all compilation commands as your normal
user; only the Debian distribution step requires `sudo`.

### Select the Board Configuration Safely

The top-level Makefile stores the selected board in `.last_conf`. Select it as
your normal user before using incremental targets:

```bash
make CONF=k230_canmv_01studio_emmc_defconfig
cat .last_conf
```

The expected value is:

```text
CONF=k230_canmv_01studio_emmc_defconfig
```

Running `sudo make toolchain_and_depend` as the only target does not read,
create, or update `.last_conf`, even if installation fails. Run setup separately
from configuration selection and compilation.

Do not run Buildroot compilation or configuration selection with `sudo`, and
do not use `sudo make CONF=...`. Those forms can leave `.last_conf` or build
artifacts owned by root. If `.last_conf` is already root-owned, including from
setup with an older Makefile, repair it once from your normal user's shell:

```bash
sudo chown "$(id -u):$(id -g)" .last_conf
make CONF=k230_canmv_01studio_emmc_defconfig
```

### Choose the Smallest Rebuild

| Change | Commands before `sudo make debian` |
|---|---|
| Documentation only | No build required |
| Interrupted build, rootfs overlay, post-build script, or post-image script | `make buildroot` |
| One local Buildroot package or AI application | `make <pkg>-dirclean`, `make <pkg>`, `make buildroot` |
| Shared library used by other packages | Clean the library and affected dependents, then `make buildroot` |
| Kernel configuration changed in the existing build tree | `make linux-rebuild`, then `make buildroot` |
| Kernel patch, DTS patch, kernel defconfig, or config fragment | `make linux-dirclean`, then `make buildroot` |
| U-Boot overlay source | `make uboot-rebuild`, then `make buildroot` |
| OpenSBI overlay source | `make opensbi-rebuild`, then `make buildroot` |
| Buildroot package selection | `make menuconfig`, optionally `make savedefconfig`, then `make buildroot` |
| Board defconfig or toolchain setting | Reselect the defconfig and run `make buildroot`; use a fresh output directory if the ABI or architecture changed |

`make <pkg>` installs that package into Buildroot's staging or target tree, but
it does not guarantee that the root filesystem and disk images have been
regenerated. Finish component rebuilds with `make buildroot` when an updated
flash or Debian image is required.

### Package and Application Source

Packages under `buildroot-overlay/package/` commonly copy local source into a
generated package build directory. Use `dirclean` so Buildroot recopies the
current source instead of compiling a stale generated copy. For example:

```bash
make face_detection-dirclean
make face_detection
make buildroot
sudo make debian
```

Replace `face_detection` with the package target being changed. A plain
`<pkg>-rebuild` starts again at the build step and is appropriate only when the
package build directory already contains the intended source.

When changing a shared static library such as AI `common`, also clean every
application that links it so those applications are relinked:

```bash
make common-dirclean
make face_detection-dirclean
make buildroot
sudo make debian
```

Add the `-dirclean` target for each affected dependent application before the
single `make buildroot` command.

### Kernel, DTB, U-Boot, and OpenSBI

For kernel changes made through `make linux-menuconfig` in the existing build
tree:

```bash
make linux-rebuild
make buildroot
sudo make debian
```

For tracked kernel patches, DTS changes carried by patches, kernel defconfig,
or configuration fragments, use `dirclean` so Buildroot extracts the kernel
again and reapplies the patches and configuration:

```bash
make linux-dirclean
make buildroot
sudo make debian
```

For U-Boot or OpenSBI overlay source, rebuild only that boot component:

```bash
make uboot-rebuild
make buildroot
sudo make debian
```

```bash
make opensbi-rebuild
make buildroot
sudo make debian
```

### Root Filesystem and Debian Image

Changes under `buildroot-overlay/board/canaan/k230-soc/rootfs_overlay/`, or in
the post-build and post-image scripts, do not require recompiling every
package:

```bash
make buildroot
sudo make debian
```

If no Buildroot input changed and only a fresh Debian image is needed, reuse
the existing base artifacts:

```bash
test -f output/k230_canmv_01studio_emmc_defconfig/images/sysimage-sdcard.img
sudo make debian
```

## Flash the eMMC Board

Use the Kendryte K230BurningTool GUI on Windows over USB.

Flash this image:

```text
output/k230_canmv_01studio_emmc_defconfig/images/debian.img.gz
```

The versioned symlink in the same directory points to the same image and is also valid.

One-time Windows driver setup:

1. Download `zadig-2.8.exe` and K230BurningTool.
2. Put the board into USB burning mode and connect it to the Windows PC.
3. In Device Manager, confirm the board appears as a USB device.
4. Run Zadig, select the K230 device, and install the driver.
5. Confirm Device Manager no longer shows a warning icon.

Enter USB burning mode with one of these:

| Method | When to use |
|---|---|
| No valid firmware on eMMC | First flash or erased eMMC |
| Hold `BOOT` while powering on | Normal reflash path |
| `reboot_to_upgrade` | When old firmware still boots into RT-Smart |

After flashing, power-cycle the board. On serial console, boot should progress through U-Boot, OpenSBI, Linux, and then Debian.

## On-Device Notes

Check IP routing:

```bash
ip a
```

Bring up WiFi with the SDK helper:

```bash
sta.sh wlan0 <SSID> <password>
```

Persist WiFi credentials through U-Boot environment variables:

```bash
fw_setenv wlanssid <SSID>
fw_setenv wlanpass <password>
reboot
```

Bring up `wlan0` with `/etc/network/interfaces`:

```bash
ifup wlan0
```

## Manual IMX335 USB Camera

The IMX335 configuration installs `k230-camera` for manual use; it has no boot
service. Stop manually launched camera, UVC, and display applications first.
Run as root with `vvcam.service` active and `/dev/video1` available.
Run from UART or a network session: USB camera mode replaces USB ADB/MTP and
can disconnect a USB shell.

```bash
k230-camera            # USB camera plus best-effort LCD preview
k230-camera --no-lcd   # USB camera only
```

The UVC gadget uses pid.codes VID `0x1209` and PID `0x0001` for testing only.
Replace these IDs before production use.

UVC uses `/dev/video1` and defaults to MJPEG 2592x1944 at a nominal 30 fps.
The host can also select 640x360, 1280x720, or 1920x1080. Select MJPEG
2592x1944 explicitly in PotPlayer if Windows retains an earlier resolution.
The USB high-speed endpoint uses interval 1 and a maximum packet setting of
1024 bytes. Board testing produced clean headless 2592x1944 video at a reported
30 fps with 1024; 2048 and 3072 showed corruption on this board/host setup.
These results implicate the USB multi-transaction path but do not establish
its precise driver or host-side cause. JPEG quality remains 50 (1-100) and is
not automatically reduced to maintain frame rate. Delivered throughput still
depends on scene complexity and host behavior.

Encoded frames are no longer periodically discarded. Recheck cold-start
behavior and simultaneous LCD/UVC operation on the rebuilt image.

The optional LCD preview uses `/dev/video2`, an
800x480 output, and rotation 1. LCD setup is best effort and does not detect
whether a physical panel is connected. UVC retries every three seconds after
failure. Press Ctrl+C to clean up and restore previously active ADB/MTP.
Logs are `/run/k230-camera/uvc.log`, `/run/k230-camera/lcd.log`, and
`/run/k230-camera/gadget.log`.

To enable the package in an existing IMX335 build and rebuild changed packages:

```bash
make CONF=k230_canmv_iadiy_emmc_imx335_uvc_defconfig
# Remove obsolete generated patches when reusing a diagnostic build tree.
# SDK overlay synchronization copies files without deleting removed files.
rm -f output/buildroot-2025.02.1/package/uvc-gadget/0004-vpu-warm-up-capture-before-encoding.patch
rm -f output/buildroot-2025.02.1/package/uvc-gadget/0005-vpu-add-opt-in-uvc-buffer-diagnostic-dump.patch
make vvcam-dirclean
make vvcam
make ffmpeg-dirclean
make ffmpeg
make uvc-gadget-dirclean
make uvc-gadget
make k230_camera-rebuild
make buildroot
sudo make debian
```

The Debian package is generated as `images/deb/k230-camera.deb` in that
configuration's output directory. Validate full-resolution image geometry,
sustained encoder and receiver frame rates, smaller UVC resolutions, repeated
launches, and operation with and without LCD preview. Measure frame counts
against elapsed wall-clock time; the VVCAM timestamp/sequence metadata is not
reliable for FPS measurement.
